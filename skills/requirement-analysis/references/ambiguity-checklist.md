# 需求质量检查:歧义词与需求缺陷模式

需求文档自身的缺陷是测试点遗漏的最大来源。分析时逐段扫描本清单,
命中的每一处都必须记入「需求疑问」,**禁止自行解释后静默放过**。

## 一、不可测试词黑名单(出现即追问)

| 词 | 为什么不可测试 | 追问方式 |
|---|---|---|
| 尽量 / 尽可能 | 没有判定标准 | "尽量"到什么程度?下限是什么? |
| 合理 / 合适的 | 谁的理?什么标准? | 给出具体规则或示例 |
| 快速 / 及时 / 高性能 | 无量化指标 | P95 响应时间?多少毫秒/秒? |
| 大量 / 高并发 | 无数量级 | 具体多少条?多少 QPS? |
| 正常 / 友好 / 易用 | 主观描述 | 可观察的判定标准是什么? |
| 等 / 等等 / 诸如此类 | 范围不封闭 | 完整枚举是什么? |
| 必要时 / 视情况 | 条件不明 | 什么条件触发?谁判断? |
| 支持多种格式 | 范围不明 | 具体哪几种?每种的要求? |
| 用户 / 管理员(未定义) | 角色模糊 | 角色的权限边界是什么? |

## 二、常见需求缺陷模式

### 1. 只写主流程,没有异常路径
- 症状:通篇"用户做 X,系统做 Y",没有"如果失败""如果超时""如果重复";
- 追问:每个写操作失败时用户看到什么?数据处于什么状态?

### 2. 状态机不完整
- 症状:只写状态前进(待支付→已支付),没写取消、超时、回退、终态;
- 追问:每个状态能到达哪些状态?谁触发?有没有终态?非法迁移怎么办?

### 3. 缺验收标准
- 症状:有功能描述,没有"做到什么程度算完成";
- 追问:这个功能怎么算做对?怎么算做错?

### 4. 单位与精度缺失
- 症状:金额没写小数位与舍入规则;时间没写时区;数量没写上限;百分比没写基数;
- 追问:金额保留几位?四舍五入还是截断?时间按哪个时区?

### 5. 角色权限矩阵缺失
- 症状:出现多个角色但没说每个角色能做什么、不能做什么;
- 追问:给出 角色 × 功能 的权限矩阵。

### 6. 数据生命周期缺失
- 症状:只写创建,没写修改/删除/归档/保留期限;
- 追问:数据能删吗?删除是物理删还是逻辑删?被引用的数据能删吗?保留多久?

### 7. 依赖外部系统但行为未定义
- 症状:接了短信/支付/地图等第三方,但没写第三方不可用、超时、返回异常时怎么办;
- 追问:每个外部依赖的降级策略是什么?

### 8. 数字规则前后矛盾
- 症状:前文"密码 6-20 位",后文"密码至少 8 位";
- 追问:指出矛盾位置,请需求方裁定,记录结论前按更严格的口径设计。

### 9. 没有定义"空"与"默认"
- 症状:列表为空显示什么?字段没填存 null 还是空串?默认值是什么?
- 追问:每个展示型字段的空态表现。

## 三、处理方式

1. 每处缺陷记入测试点文档的「需求疑问」清单,格式:`Q<序号>:<问题描述>,按"<临时假设>"设计,待确认`;
2. 临时假设同时记入「假设记录」,相关测试点照常设计(不阻塞流程);
3. 向用户汇报时,需求疑问清单必须原文呈现,让用户逐条确认。
