# 用例设计技术详解

## 1. 等价类划分

把输入域划分为若干等价类,类内任一值暴露缺陷的能力相同,每类取一个代表值。

操作步骤:
1. 列出输入项及其约束(类型、长度、取值范围、格式);
2. 每个约束分出**有效等价类**(满足)和**无效等价类**(违反,一种违反方式一类);
3. 有效等价类尽量合并到少量用例(强组合),无效等价类**一类一条用例**
   (避免缺陷屏蔽:一条用例同时违反两个约束,前一个报错会掩盖后一个)。

## 2. 边界值分析

缺陷密集分布在边界上。对每个有序输入(数值、长度、时间、数量):
- 取 6 点:`min-1, min, min+1, max-1, max, max+1`;
- 开放边界(只限下限或上限)只取对应 3 点;
- 时间类注意特殊边界:0 点、月末、闰年 2/29、夏令时;
- 分页类边界:总数=0、总数=页大小、总数=页大小+1;
- 金额类边界:0、0.01、精度上限(如 0.001 是否被截断)、上限值。

## 3. 判定表

适用:多个条件共同决定结果,且规则间有优先级或互斥。

操作步骤:
1. 列出所有条件桩(布尔化,每个条件只取真/假)和动作桩;
2. 全组合 2^n 列,n ≤ 5 时直接全列;
3. 合并无关项(某条件不影响结果时合并,标「—」);
4. 每列规则 = 一条用例;**不可能出现的组合**单独验证系统是否拦截。

示例(登录):

| 条件 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| 账号存在 | T | T | F | F |
| 密码正确 | T | F | — | — |
| 动作:登录成功 | ✓ | | | |
| 动作:提示密码错误 | | ✓ | | |
| 动作:提示账号不存在 | | | ✓ | ✓ |

## 4. 因果图

适用:条件之间存在**依赖/约束**关系(如"选了 A 才允许选 B"),直接列判定表
会产生大量无意义组合时。

操作步骤:
1. 列出原因(条件)与结果(动作);
2. 标注因果关系(恒等/非/或/与)与约束关系(互斥 E、包含 I、唯一 O、要求 R、屏蔽 M);
3. 把因果图转成判定表,剔除违反约束的组合;
4. 每个有效组合 = 一条用例。

与判定表的分工:条件独立直接用判定表;条件有约束先画因果图。

## 5. 状态迁移

适用:对象有明确生命周期(订单:待支付→已支付→已发货→已完成/已取消)。

操作步骤:
1. 从文档提取全部状态与触发事件,画出状态迁移图(写进「设计过程」附录);
2. 覆盖每条**合法迁移**(一条迁移至少一条用例);
3. 针对关键状态验证**非法迁移被拒绝**(如已取消订单不能再支付);
4. 覆盖**迁移中的事件**:支付回调与超时关单同时发生、迁移中途失败回滚;
5. 覆盖**终态**:到达终态后所有操作应被拒绝。

## 6. 场景法

适用:端到端业务流程。从用例规约中提取基本流与备选流:
- 基本流:1 条主场景用例;
- 每个备选流(异常分支、可选分支):至少 1 条场景用例;
- 备选流组合:高风险组合补充场景(如"库存不足 + 优惠券已锁定");
- 每条场景用例走完整流程(从入口到出口),验证状态流转和数据落库,
  而不是只验证单个页面。

## 7. 正交试验与 Pairwise

适用:多参数多取值的组合爆炸(如兼容性:5 浏览器 × 3 系统 × 2 分辨率 = 30 组)。

- **正交表**:选 L9/L16 等正交表裁剪组合数,保证任意两因素组合均匀覆盖;
- **Pairwise(成对组合)**:只保证任意两个参数的取值组合都出现至少一次,
  组合数比正交更少,适合因素多(≥4)的场景;
- 两者之外,把业务上已知的高风险组合**手动补回**(裁剪算法不保证覆盖特定组合);
- 决策:因素 ≤3 全组合;因素 4-6 用正交/Pairwise;因素更多时先按业务聚类再裁剪。

## 8. 接口用例设计

适用:测试点涉及 API(需求文档含接口定义,或前后端分离场景)。

维度与步骤:
1. **参数校验矩阵**:每个参数 × (缺失/为空/类型错误/超长/非法值/边界值),
   等价类+边界值在参数级应用;
2. **业务规则**:同功能用例(判定表/状态迁移在接口层复用);
3. **契约验证**:返回结构、字段类型、错误码与文档一致;多余敏感字段
   (密码、身份证)不得返回;
4. **安全**:未认证(无 token/过期 token)、越权(改 ID 访问他人资源)、
   SQL 注入、参数篡改(金额、数量为负数或超大值);
5. **幂等与并发**:同一请求重发(带幂等键/不带)、并发请求同一资源;
6. **性能冒烟**(如声明指标):单次调用响应时间抽查。

## 9. 非功能用例设计

非功能测试点转成用例的关键是**量化 + 场景化**:没有量化指标的先回
requirement-analysis 的「需求疑问」确认,仍无指标则按行业默认并标注假设。

- **性能用例**:写明场景(多少数据量/多少并发)、动作、量化预期
  ("1000 条数据下列表加载 < 2s");
- **安全用例**:按 OWASP 常见项场景化(注入、越权、敏感数据泄露、会话固定),
  预期结果是"被拦截/不泄露/有审计日志";
- **兼容性用例**:来自正交/Pairwise 裁剪后的组合矩阵,每组一条;
- **可靠性用例**:故障注入场景(断网、超时、第三方不可用)+ 降级预期。

## 10. 错误推测

凭经验补充的高危场景,放在最后兜底:
- 历史线上缺陷的同类场景;
- 时序类:重复提交、会话过期瞬间操作、回退键;
- 数据类:超长字符串、全角/半角、Emoji、null 与空串差异、前后空格;
- 资源类:磁盘满、内存不足、弱网;
- 时区类:跨时区显示、跨零点/跨月的统计口径。
