# 测试数据设计

用例的测试数据必须**具体化**:评审者不看需求文档也能照着执行。
"一个合法手机号""较大的金额"这类描述一律不合格。

## 一、数据设计原则

1. **具体**:写到可以直接输入的值("手机号 13800001111",不是"合法手机号");
2. **多样**:同一字段的不同用例用不同的值,避免一个值测全部(缺陷可能被值掩盖);
3. **可重复**:数据在测试环境可稳定准备(前置条件写明怎么造);
4. **隔离**:每条用例的数据不依赖其他用例的执行结果(除非明确声明串行)。

## 二、常用字段的典型数据集

| 字段类型 | 正常值 | 边界值 | 脏数据 |
|---|---|---|---|
| 手机号 | 13800001111 | 10 位 / 12 位 | 字母开头、含空格、+8613800001111 |
| 邮箱 | zhang.san@test.com | 64 字符本地部分 | 无 @、双 @、中文、前后空格 |
| 密码 | Abc123(6 位) | 5 位 / 20 位 / 21 位 | 纯数字、纯字母、含 Emoji、全角字符 |
| 金额 | 100.00 | 0、0.01、999999999.99 | 0.001(超精度)、-1、千分位"1,000" |
| 日期 | 2026-09-19 | 月末 09-30、闰年 02-29、23:59:59 | 02-30、13 月、1970-01-01、9999-12-31 |
| 字符串 | 张三 | 长度下限/上限 | Emoji👨‍👩‍👧、`<script>alert(1)</script>`、`' OR 1=1 --`、换行符、全角空格 |
| 枚举 | 文档定义的每个值 | — | 文档外的值、大小写变体、null、空串 |
| 文件 | 正常 jpg/png | 大小上限、上限+1B | 空文件、改后缀的 exe、损坏文件、同名文件 |

## 三、数据准备策略(写进前置条件)

按优先级选择造数方式,并在前置条件中注明:
1. **已有基础数据**:"使用预置账号 test001/Test@123"(最稳定,优先);
2. **接口造数**:"调用注册接口创建账号,手机号 13900002222";
3. **UI 造数**:"先在注册页完成注册"(最慢,仅无法绕过 UI 时用);
4. **特殊状态数据**:写明如何到达该状态("先连续输错密码 4 次")。

## 四、容易遗漏的数据场景

- **null 与空串差异**:接口传 null、"\"\""、不传该字段,三种行为可能不同;
- **前后空格**:" 张三 " 是否 trim,存储与展示是否一致;
- **大小写**:用户名/邮箱登录是否大小写敏感;
- **编码**:中文、Emoji、繁体、特殊符号在存储/搜索/导出中的一致性;
- **时区**:UTC+8 与 UTC 混用导致跨零点统计错位;
- **历史脏数据**:老数据不符合新规则时的兼容表现(如历史手机号位数不足)。

## 五、安全与脱敏

- 用例中禁止使用真实用户数据(真实手机号、身份证、银行卡);
- 示例数据用保留段:手机号 1380000xxxx、身份证 11010119900101xxxx、
  银行卡 6222 0000 0000 0000;
- 涉及敏感数据的用例,预期结果中必须写明脱敏展示形式(如 138****1111)。
