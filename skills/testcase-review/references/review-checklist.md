# 用例评审检查清单

## 可追溯性
- [ ] 每个测试点(TP)至少一条用例覆盖,能列出 TP → TC 对应关系
- [ ] 每条用例能回指到一个测试点,无来源的用例已标注「疑似臆测」
- [ ] 需求疑问清单中的条目,相关用例已体现假设处理方式
- [ ] 设计中间产物(判定表/状态图)与最终用例一致,无"列了表但用例没按表展开"

## 可执行性
- [ ] 前置条件分层写明:环境(浏览器/版本)、账号(角色/权限)、数据(具体到值)
- [ ] 测试数据具体(具体手机号/金额/字符串,而非"合法数据")
- [ ] 步骤有明确的操作对象和操作方式(点哪个按钮、在哪个页面)
- [ ] 步骤之间顺序正确,可独立复现,不依赖其他用例的执行结果
- [ ] 特殊状态的前置条件写明到达路径(如"先连续输错密码 4 次")
- [ ] 他人(非设计者)照步骤能原样执行

## 可判定性
- [ ] 预期结果可观察:页面文案、跳转地址、状态变化、数据落库
- [ ] 无"正常""正确""成功""合理"等无判定标准的词
- [ ] 预期结果与步骤一一对应(步骤有 N 个动作,预期覆盖每个动作的结果)
- [ ] 涉及数据的用例,预期写明数据层面的验证(如列表新增一条记录、库存由 10 变 9)
- [ ] 涉及状态流转的用例,预期写明流转后的状态

## 覆盖度
- [ ] 每个测试点至少一条用例,编号可追溯
- [ ] 正常 / 边界 / 异常 / 权限 / 安全 / 数据各维度均有体现
- [ ] 异常场景占比 ≥ 30%
- [ ] 主流程端到端场景存在且为 P0
- [ ] 资金/库存/计数类功能有幂等(重复提交)与并发用例
- [ ] 有状态生命周期的对象,合法迁移全覆盖 + 关键非法迁移被拒绝
- [ ] 非功能测试点(性能/安全/兼容)已转化为量化用例,未量化的已标注假设

## 安全性专项
- [ ] 未登录/过期 token 访问受保护资源的用例存在
- [ ] 横向越权(操作他人数据)与纵向越权(低权限用高权限功能)用例存在
- [ ] 敏感字段(密码/身份证/银行卡/手机号)的脱敏展示与接口返回已验证
- [ ] 注入类输入(SQL/XSS)至少各一条用例
- [ ] 防枚举场景(登录/找回密码的统一提示)已覆盖

## 经济性
- [ ] 无完全重复的用例(步骤与预期相同)
- [ ] 无互相包含的用例(A 的步骤是 B 的子集且预期相同,删 A)
- [ ] 等价类代表值不重复覆盖同一等价类
- [ ] 一条用例只验证一个测试点,无"顺便验证"的多断言用例

## 优先级
- [ ] P0:主流程阻断、资金、数据安全,占比 10%-20%
- [ ] P1:重要功能、高频异常
- [ ] P2:一般功能、低频边界
- [ ] P3:文案、兼容性细节、极端边缘
- [ ] 定级与业务影响一致,无"全是 P1"的偷懒定级
- [ ] 资损/数据丢失/安全泄露/主流程阻断场景全部是 P0

## 格式(导出工具硬性要求)
- [ ] 六列,顺序:用例编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级
- [ ] 单元格内无 `|` 符号、无换行(多步用「;」分隔)
- [ ] 编号 TC-<模块缩写>-<三位序号>,无重复、无跳号
- [ ] 优先级仅为 P0/P1/P2/P3,无"高/中/低"
- [ ] 表头与约定完全一致(差一个字工具都会拒绝)
